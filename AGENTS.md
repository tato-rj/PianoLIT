# PianoLIT project guidance

## Purpose and compatibility

PianoLIT serves the public website, the `my.*` web app, administration, and mobile app APIs from one Laravel application. Preserve existing appearance, working behavior, route names, and mobile JSON contracts unless a task explicitly calls for a change. Favor small, demonstrated fixes over broad rewrites. The iOS v2 upgrade is now being planned separately: web changes and new v2 work must not affect existing iOS behavior, legacy mobile API contracts, or existing mobile media delivery. Do not assume a route is unused simply because this repository has no caller: mobile clients are separate.

As of 2026-10-28, v2 login, Discover and confirmed piece-open history are live at `https://pianolit.com/api/v2`; `2026_10_28_230000_create_api_v2_tokens.php` is installed in production. The new app keeps the existing email/password screen/accounts, calls `/auth/login` for a separate 30-day Keychain bearer credential and uses `/discover`; `/auth/logout` revokes only that credential. Password changes and account deletion invalidate credentials. Legacy locally stored account IDs cannot be exchanged for tokens; an upgrade without a v2 credential requires one existing-password sign-in. Preserve the legacy API indefinitely without requiring any old-app update. Web and v2 Discover use `App\Services\Discover\Feed` and `Discover\Levels` as one content source, with shared account-keyed recommendation IDs and daily artwork choices; never duplicate native selection queries or alter shared model serialization. Keep the legacy cache/feed, middleware, login JSON and original mobile media delivery unchanged. V2 uses explicit DTOs, bearer-derived identity, JSON errors and no-store responses, outside legacy/browser middleware. Native media entitlement and complete detail/search/favorites migration remain separate; do not import web access policies or restore positional Free Pick access. `docs/api/v2/manifest.yaml` revision `2026-10-28.1` and its referenced files define the handoff; the draft status now denotes pending staging/native acceptance, while backend verification and the live base URL are explicit. `scripts/api-handoff.py` checks/builds immutable bundles in `public/api-handoff/v2/`; prior revisions are immutable. Do not advance readiness without documented staging/native checks. Published files contain no secrets or real account data. See `docs/api/v2/README.md` and its UIKit-compatible Swift connection example.
